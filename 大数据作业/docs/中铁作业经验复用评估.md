# 中铁作业经验复用评估

中铁作业的经验对本次大数据作业有较高复用价值，但不能直接照搬风险分析框架。本次作业的中心概念应从“风险传导”转换为“价值创造、资源协同和成本管理”。

## 一、可以直接复用的做法

1. 目录结构
   - 继续保留 `configs/`、`data/`、`docs/`、`outputs/`、`paper/`、`scripts/`、`交付/` 的组织方式。
   - 原始资料、中间数据、最终数据分层保存，避免后期找不到证据链。

2. 来源记录
   - 所有公开资料都记录网址、发布时间、访问日期、用途和证据等级。
   - 官方公告、政策文件和公司披露优先于媒体解读。

3. 网络分析流程
   - 仍采用“节点表-边表-网络指标-可视化-管理解释”的流程。
   - 中心性、社群和关键路径仍然适用，只是解释对象从风险节点换成价值创造节点。

4. 视频表达
   - 继续使用“问题-数据-网络-发现-建议”的短视频结构。
   - 3 分钟内展示交互网络图和关键发现，避免视频中长时间运行脚本。

5. 最终交付
   - 使用中文命名的交付文件夹。
   - 报告、代码、数据、视频、依赖说明分开存放。

## 二、必须调整的地方

| 中铁作业 | 本次作业 |
| --- | --- |
| 风险事件网络 | 价值创造网络 |
| 风险类型、风险主体、传导路径 | 能源资源、算力需求、平台能力、交易市场、客户场景 |
| 风险中心性解释 | 资源聚合、调度协调、市场连接和价值分配解释 |
| 财务风险预警模型 | 社会网络指标与成本管理洞察 |
| 弹性风险管理模型 | 动态能力链条和价值共创共享演化 |

## 三、对本次作业最有用的经验

1. 不先写正文，先把数据结构搭好。
2. 节点和边的字段一开始就固定，后续报告和视频会轻松很多。
3. 模拟数据要讲清楚依据、权重和局限，不能假装是真实交易数据。
4. 图表要服务结论，尤其要把中心性指标转化成成本管理含义。
5. 报告语言要像研究分析，不写“我生成了某某文件”这类过程性表达。

## 四、建议复用的最终表达方式

本次报告可采用如下叙述逻辑：

协鑫能科的价值创造并不只发生在单一发电或单一算力环节，而是通过虚拟电厂平台把清洁能源、储能、用户负荷、电价信号、政策约束和算力需求连接起来。网络中的高中心性节点代表资源聚合和调度协调能力，关键边代表价值从能源侧向算力侧、用户侧和市场侧转移的路径。由此可以把成本管理解释为跨主体、跨场景的协同优化过程。
